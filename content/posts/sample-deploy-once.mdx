The bug that finally annoyed me into writing a tool was not a hard one. I
redeployed a contract, updated the address in the app, forgot the copy in the
test fixtures, and spent an hour watching a test pass against a contract that
no longer existed.

Nothing about this is interesting, which is exactly the problem. Every team
doing onchain work rebuilds the same fragile pipeline: a deploy script writes
an address somewhere, a human copies it into a constants file, the ABI gets
exported by a different command, and the types are generated by a third. Four
sources of truth for one deployment.

What I wanted was for the deploy to be the source of truth, and for everything
downstream to be derived from it. Deploy once, get back a typed object that
knows its own address and ABI, and hand that same object to the app, the
scripts, and the tests.

```ts
const { confidentialToken } = await deployoor.deploy("local")

// the app, the scripts and the tests all use this same object
await confidentialToken.write.transfer([bob, handle])
```

The testing half turned out to matter more than the deploy half. Running
against a real in-memory EVM instead of a mocked one means the fixtures cannot
drift, because there are no fixtures. You deploy, you use it, you throw it
away.

None of this is clever. It's the kind of tool you write because the
alternative is losing another hour to a stale constant.
